## 0. 요약

- **1500 iteration / 196.6 M env-step / 24분 21초** 완주. 파이프라인 자체는 정상이다.
- 결과 정책은 **넘어지지 않지만 움직이지 않는다**: 35 s 완주 64/64, 전진 +0.003 m, 좌면 높이 0.048 m.
  §7 합격선 3개 중 1개(완주)만 통과.
- **과적합이 아니다.** Table IV 를 그대로 옮긴 보상에서 "굳기"는 정확한 최적해다. 논문 자신의
  걸음새조차 Table IV 기준으로는 정지보다 스텝당 손해다(§3).
- 굳은 자세가 `a_stand`(28/스텝)가 아니라 웅크림(19.8/스텝)인 이유는 **관절 한계 클립이 탐색
  노이즈를 지우기 때문**이다. iter 50에 이미 정책 출력의 100% 가 ±50° 밖으로 나가 있고, 최종
  정책은 6관절 중 5개가 한계에 박혀 있다. 그 관절들에는 탐색이 물리적으로 존재하지 않는다(§4).
- 중간 클립에서 보이는 "걷는 개체"는 학습된 보행이 아니라 **남은 한 관절의 탐색 노이즈가 만든
  후진**이고, progress 항이 그걸 처벌해서 제거했다(§5).
- 논문 정책 `walk.onnx` 는 우리 시뮬에서 관절 순서 3종 × 쿼터니언 부호 2종 전부 몇 스텝 안에
  넘어진다. §7 축 2 기준선은 아직 쓸 수 없다 — §2 system ID 와 관절 대응 실측이 선행조건(§7).

논문 Table IV 는 IsaacGymEnvs Ant/Humanoid 의 보상(progress=P−P_pre, up/heading 0.93·0.8, alive,
death, action, vel)을 항목 그대로 가져왔다. Ant(Isaac Lab `direct/ant/ant_env.py`, IsaacGymEnvs 값)와
같은 자로 놓으면:

| 스텝당 보상 | Ant | 논문 Table IV (dt=0.1, 논문 명시) |
|---|---|---|
| 정지 보너스 alive+up+heading(+height) | **1.10** | **28** |
| progress, 실제 달성 속도에서 | 1.0–6.0 (0.5–3 m/s, /sim.dt) | **0.75** (Fig.11: 10 s 에 x≈0.25 m) |
| action cost | 0.005·Σa² ≈ 0.01 (**크기**, 무시 가능) | 2·‖a−a_pre‖² ≈ **2.4–3.5** (Fig.11 진동 진폭 기준, **변화량**) |

## 4. 진단 2 — 관절 한계 클립이 탐색을 지운다 (Ant 와의 결정적 차이)

env 는 이력에는 raw 액션을, 관절에는 `clamp(±ACTION_LIMIT)` 를 준다(실기 계약, §3). 따라서 `mu` 가
한계 밖이면 `mu + σε` 를 아무리 뽑아도 관절엔 전부 ±50° 가 간다 — **클립이 탐색 노이즈를 지운다.**
체크포인트별 `|mu| > ACTION_LIMIT` 비율(64 env × 200 스텝, mu 결정론):

| iter | σ | 포화율 | 관절별 (정책순서 0..5) | 평균 mu |
|---|---|---|---|---|
| 50 | 0.91 | **100 %** | 6/6 | ≈ 190° (3.3 rad) |
| 200 | 0.69 | 100 % | 6/6 | 300–800° |
| 400 | 0.68 | 100 % | 6/6 | 1000–1800° |
| 750 | 0.58 | 98 % | idx 2 만 85 % | idx 2: 112° |
| 900–1499 | 0.48→0.22 | 83 % | **5/6 = 100 %, idx 2 = 0–1 %** | idx 2 ≈ 0°, 나머지 300–2900° |

최종 자세(평균 관절각, 정책순서) `[50, 50, −18.6, 50, 50, 50]°` — 6개 중 5개가 기계 한계. 이 관절들에
대해 PPO 에는 **탐색이 물리적으로 존재하지 않는다.** σ 가 얼마든 관절은 안 움직인다. 진동 보행을
우연히라도 발견할 경로는 iter 50에 닫혔다.

`mu` 가 50 rad(2900°)까지 도망간 이유: Table IV 의 action cost 는 **변화량**에만 걸린다. 일정한
mu=50 rad 는 비용 0 이다. 크기를 벌하는 항이 없으므로 mu 는 얼마든지 커질 수 있고, 커질수록 노이즈가
더 확실히 지워진다. Ant 는 action cost 가 크기(Σa²)이고 rl_games 가 env 앞에서 클립한다.

왜 `a_stand`(28) 가 아니라 웅크림(19.8)인가: `a_stand` 는 한계 안쪽이라 노이즈가 살아 있고,
무작위 액션 std 0.05 rad(2.9°) 만으로도 평균 11.9 스텝에 넘어진다(std 1.0: 3.1 스텝, 0.25: 3.7,
0.1: 5.7 — 256 env 실측). 한계에 박힌 낮은 자세는 노이즈 면역 + 정적 안정이다. σ 가 0.22 까지
줄어도 `a_stand` 로 돌아갈 gradient 가 그 관절들엔 없다.

## 5. 학습 단계 해석

- **iter 0–50**: σ=1, 포화 38 %, 3 스텝에 넘어짐. PPO 가 처음 찾은 생존책 = "전부 한계로 밀어라".
  iter 50 에 100 % 포화, eplen 3→67.
- **iter 100–600**: 웅크림 정착(z 0.046), 보상 3000대 정체. 실질 최적화는 여기서 끝.
- **iter 650–900**: idx 2(= `joint4`, 뒷다리 좌우 스윙 힌지)가 포화에서 풀림. 유일한 자유 관절의
  노이즈가 후진을 만들고(표본 롤아웃 −0.6 m) progress 가 처벌, eplen 88 까지 급락. 학습 클립의
  "걷는 개체"는 이 구간이다.
- **iter 900–1500**: σ 0.48→0.22. 남은 한 관절의 노이즈를 지우는 것만으로 3300→6384.

후반의 굳기는 중반의 후진 노이즈를 progress 항이 제거한 결과다. 후진 편향의 역학(뒷다리 한 개의
좌우 지터가 마찰로 정류되는 방향)은 **가설**이며 검증하지 않았다.

## 6. 논문은 같은 표로 어떻게 걸었나 (후보, 미검증)

1. **시뮬이 "가만히 있기"를 허락하지 않았을 가능성.** 논문은 `dt = 0.1 : Period of simulator` 라고
   적었고, 액추에이터를 MuJoCo 뷰어에서 손으로 맞췄다. 그 MJCF 의 timestep 0.016 은 서 있지도
   못하고 발산한다(스펙 §2⑤). 거친 시간 스텝에서는 정적 자세 자체가 떨리고, "몸통을 위아래로
   흔들어 전진"은 그 떨림을 이용한 걸음새일 수 있다. 우리 1/120 s 시뮬은 굳기가 완벽히 안정하다.
2. **2단계 노이즈 학습(§6).** 물리·센서·액션 노이즈가 들어가면 정적 자세는 능동 균형 없이 못 버틴다.
   우리는 1단계만 돌렸다.
3. **131,072 env** — 우리의 32배. 표가 보행을 선호하지 않을 때 "우연히 앞으로 가며 살아남은" 희귀
   표본이 매 배치에 있어야 advantage 가 잡힌다.

논문 최종 정책의 σ 는 `walk.onnx` 초기화자에서 읽힌다: `exp(sigma) = [0.055, 0.066, 0.086, 0.091,
0.046, 0.049]`(평균 0.066) — 우리(0.22)보다 훨씬 작다. 그들도 탐색을 죽였지만 **죽이기 전에 진동
걸음새를 먼저 잡았다.** 순서 싸움이다.

## 7. 논문 정책 `walk.onnx` 를 우리 시뮬에 (§7 축 2)

`walk.onnx` 그래프(Sub/Div/Clip[±5] → Gemm/ELU → Gemm/ELU → Gemm mu)를 torch 로 재구현
(onnxruntime 대조 최대오차 7e-7), 관절 순서 후보 3종(`tree`/`actuator`/`tree-reversed`,
`chair_sim.JOINT_ORDERS`) × 쿼터니언 부호 2종((x,y,z,w) / (−x,−y,z,w)) 을 64 env × 340 스텝:

| 조합 | 생존 | z | 보상/스텝 | act | vel |
|---|---|---|---|---|---|
| tree, (x,y,z,w) | 0/64 | 0.077 | 16.9 | −6.4 | −1.8 |
| tree, (−x,−y,z,w) | 0/64 | 0.078 | 19.4 | −6.8 | −1.1 |
| actuator, (x,y,z,w) | 0/64 | 0.075 | 11.5 | −15.1 | −1.3 |
| actuator, (−x,−y,z,w) | 0/64 | 0.079 | 12.0 | −12.9 | −1.3 |
| tree-rev, (x,y,z,w) | 0/64 | 0.079 | 17.5 | −7.7 | −1.1 |
| tree-rev, (−x,−y,z,w) | 0/64 | 0.075 | 11.7 | −13.4 | −1.2 |

전부 몇 스텝 안에 넘어진다. 스펙 §7 이 예고한 대로 "우리 정책이 나쁜 것"이 아니라 **§2 system ID
가 덜 끝났고 관절 대응(정책 인덱스 ↔ 관절 이름)이 미확정**이라는 신호다. 축 2 기준선은 이 둘이
닫히기 전엔 못 쓴다. 넘어지기 전 보상 11–19/스텝은 웅크림(19.8)과 동급 — 논문 걸음새가 Table IV
의 최적해가 아니라는 §3 의 산술과 일치한다.

## 8. 후속 손잡이 (우선순위, 전부 이슈 #15 밖)

1. **mu 폭주 차단** — 크기 페널티(Ant 식 Σa², 또는 한계 초과분만) 또는 출력 squash. 5/6 관절의
   탐색이 죽는 걸 막는 것이 다른 모든 튜닝의 전제다. **실기 계약과 얽힌다**: 이력에는 raw mu 가
   들어가야 하므로(§3) 래퍼 클립(`clip_actions`)으로 풀면 학습(클립값)과 실기(raw)의 이력 분포가
   어긋난다. 정책 출력 자체를 유계로 만드는 쪽이어야 한다.
2. **정지가 안정하지 않게 만들기** — §6 액션·센서 노이즈를 1단계부터, 또는 물리 dt 를 논문 쪽으로.
   §6 의 후보 1·2 를 직접 겨냥한다.
3. **entropy 계수 / σ 하한** — 탐색 순서 문제의 보조 수단. 1 없이는 5/6 관절에 닿지 않는다.
4. 보상 가중치 — 논문값이라 마지막.

별도 선행조건: `walk.onnx` 가 우리 시뮬에서 서지 못한다(§7) → §2 system ID + 관절 대응 실측.

## 9. 측정 방법 (재현)

환경: conda `env_isaaclab`, 저장소 루트, `PYTHONPATH=` 비움. 진단 스크립트는 세션 스크래치에서
돌린 일회용이라 커밋하지 않았다 — 아래 정의대로 다시 쓰면 된다(`eval.py` 이슈에서 정식화).

- **정책 로드**: `WalkPPORunnerCfg()` 를 `handle_deprecated_rsl_rl_cfg(cfg, version('rsl-rl-lib'))`
  로 통과시킨 뒤 `OnPolicyRunner(env, cfg.to_dict(), log_dir=None)`, `runner.load(ckpt)`,
  `runner.get_inference_policy()`. 결정론 = `policy(obs)`, 확률적 = `policy(obs, stochastic_output=True)`.
  σ 는 한 번 `stochastic_output=True` 로 호출한 뒤 `policy.output_std`.
- **롤아웃**: `RslRlVecEnvWrapper(raw, clip_actions=None)`. `raw.reset()` 포함 전체를
  `torch.inference_mode()` **안에서** 돈다(밖이면 `write_joint_state_to_sim` 이 inference tensor
  갱신으로 죽는다). obs 는 TensorDict — `obs["policy"]`.
- **전진 거리**: `raw.root_pos_local()` 을 스텝마다 읽되, **340 스텝까지만** 돈다. 350 에서
  truncation 리셋이 돌면 `_reset_idx` 가 x·y 를 정확히 0 으로 되돌려 "변위 0.000000" 이라는 허수가
  나온다(이 분석 초반에 실제로 그렇게 잘못 보고했다). 그 스텝에 `reset_terminated` 인 env 는 집계
  에서 제외한다.
- **보상 항**: `mdp.walk_reward_terms(root_pos_local, quat_xyzw, potentials, a, a_prev, joint_vel)`
  를 직접 호출해 항별 누적. `potentials` 는 `mdp.potential(p0, P_TARGET)` 로 시작.
- **포화율**: 스텝마다 `(mu.abs() > ol.ACTION_LIMIT).float().mean(0)`.
- **무작위 액션 생존 곡선**: `torch.randn(N,6)*std` 를 액션으로 120 스텝, 종료까지 스텝 수.
- **`walk.onnx`**: `onnx.numpy_helper` 로 초기화자를 읽어 torch 로 재구현, onnxruntime 과 대조.
  관절 순서 후보는 정책 출력을 `perm` 으로 재배열해 env 의 `tree` 순서에 맞추고, 액션 이력 구간
  (obs[16:])도 같은 `perm` 의 역으로 논문 순서로 되돌려 입력한다.
- **학습 실행 판정**: hydra 가 예외를 삼키고 exit 0 을 낸다. 종료코드가 아니라 로그의
  `Learning iteration` 으로 판단한다(`isaac/scripts/rsl_rl/train.py` docstring).
